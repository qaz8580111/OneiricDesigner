# 中央商店商品及价格清单

> 用途：主场景中央商店（5 分钟后出现）的商品分类、价格体系与商品来源对照。
> 数据来源：`scripts/entities/Shop.gd`（生成器与价格常量）、`scripts/resources/shop/ShopProduct.gd`（商品数据）。
> 装备化重构后，商店商品统一落在「装备体系」内：装备类由 `UpgradeManager.generate_equipment()`
> 随机生成（含词条/特效/护盾/主动技能），血包直接回核心血量。新增商品无需改 UI，只需扩展生成器。

---

## 一、商店运行规则

| 项目 | 规则 |
|---|---|
| 出现时机 | 游戏进行满 **5 分钟** 后，在竞技场正中心 `Vector2.ZERO` 生成 |
| 存续 | 生成后**永久存在，不再消失** |
| 进入方式 | 玩家靠近后按 E 进入商店（交互优先级：神庙 > 商店 > 拾取物） |
| 暂停 | 进入商店即暂停游戏（`GameManager.pause_game`），离开商店恢复 |
| 货币 | 梦境碎片（`Player.dream_fragment`） |
| 刷新间隔 | 每 **60 秒** 随机刷新一次货架 |
| 货架数量 | 每次 **3 件** 商品，横向排开 |
| 品类概率 | 装备类 80% / 血包 20% |

---

## 二、价格体系总表（梦境碎片）

| 品类 | 档位 | 价格 |
|---|---|---|
| 装备类 | 普通（稀有度 0） | **60** |
| 装备类 | 稀有（稀有度 1） | **120** |
| 装备类 | 史诗（稀有度 2） | **220** |
| 血包 | 固定 | **20**（恢复 30 点核心血量） |

> 价格常量定义在 `scripts/entities/Shop.gd` 常量区：
> `PRICE_EQUIPMENT_COMMON = 60` / `PRICE_EQUIPMENT_RARE = 120` / `PRICE_EQUIPMENT_EPIC = 220` /
> `PRICE_HEALTH = 20`（`HEALTH_AMOUNT = 30`），与上表一一对应。
> 装备价格由生成时 roll 出的 `rarity` 决定，玩家无法预知货架装备的稀有度。

## 三、各类商品来源与价格明细

### 3.1 装备类（`ProductType.EQUIPMENT`）

装备类由 `UpgradeManager.generate_equipment()` 现场随机生成，一件装备可能同时包含以下内容：

| 构成 | 生成规则（`EquipmentGenerator`） |
|---|---|
| 稀有度 | 由 `EQUIPMENT_RARITY_WEIGHTS = [76, 20, 4]` roll 出（普通 76% / 稀有 20% / 史诗 4%） |
| 槽位 | 由 `EQUIPMENT_SLOT_WEIGHTS = [22, 20, 18, 14, 13, 13]` roll 出（武器/护甲/鞋子/盾牌/戒指/法宝） |
| 基础属性词条 | 条数按稀有度断崖递减（几何比≈0.25）；数值 = 模板最大值 × `randf_range(0.5, 1.0)` |
| 子弹特效 | 按稀有度权重命中后取 1~2 个，强度 1~3 级（复用叠层成长） |
| 护盾蓝图 | 仅盾牌槽携带，按稀有度概率附加护盾特效 |
| 主动技能 | 仅武器/戒指/法宝，命中概率 普通 5% / 稀有 25% / 史诗 60%，冷却 12/9/6 秒 ±2 抖动 |

> 玩家购买后装备进入背包（`Player.add_equipment_to_backpack`），可在装备/背包面板穿戴。
> 商品描述由 `Shop._equipment_description()` 组装：词条概览（最多 2 条）+ 特效数量 + 护盾/主动技能提示。

### 3.2 血包

| 商品 | 效果 | 价格 |
|---|---|---|
| 梦境血包 | 立即恢复 30 点核心血量 | 20 |

> 效果：`Player.heal(30)`，可被核心血量上限自然钳制（不会超上限溢出）。

## 四、购买规则

1. **扣款**：玩家选定商品后，`Shop` 先校验 `Player.dream_fragment >= 价格`，再调用
   `Player.spend_dream_fragment(价格)` 扣款，最后 `ShopProduct.apply(player)` 应用效果。
2. **余额不足**：不扣款、不发货，仅播放提示音与面板红闪提示（`ShopPanel.notify_insufficient`）。
3. **背包已满**：购买装备类商品前先做背包满预检（`Shop._is_backpack_full`），满则拒绝购买并提示；
   发货阶段若竞态失败，`Shop` 会自动**退还已扣碎片**，保证玩家不白花钱。
4. **购买后**：面板标题栏实时刷新碎片余额，商品不消失（同一件可重复购买，直到 60 秒刷新）。
5. **结算统计**：装备类经 `Player.add_equipment_to_backpack` 进入背包，穿戴后属性/特效/护盾/主动技能
   统一由 `EquipmentComponent` 汇总进 `UpgradeManager.recompute_stats()`。

---

## 五、与现有体系的关系（零侵入）

- **装备类**：复用 `UpgradeManager.generate_equipment()` 生成，与掉落、神庙「求购装备」走同一生成器，
  概率模型与词条模板（`data/upgrades/*.tres` 复用为装备词条模板）完全一致。
- **血包**：复用 `Player.heal()`，仅补充血量，不干扰装备。
- **输入**：商店经 `InputManager` 的 `SHOP_CHOICE` 上下文放行 LT/RT 左右选择、
  A 确认购买、ESC 关闭，遵守 `INPUT_ARCHITECTURE_SPEC.md`。
- **性能**：商店生成后仅单节点；商品刷新每 60 秒一次；交互范围探测节流 0.1s、
  视觉脉冲重绘节流 30fps，不对战斗帧率产生可感知影响。
