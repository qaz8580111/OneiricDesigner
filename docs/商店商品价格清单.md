# 中央商店商品及价格清单

> 用途：主场景中央商店（5 分钟后出现）的商品分类、价格体系与商品来源对照。
> 数据来源：`scripts/entities/Shop.gd`（生成器与价格常量）、`scripts/resources/shop/ShopProduct.gd`（商品数据）。
> 所有商品均落在「现有技能 / 装备体系」内：属性类与技能类取自 `data/upgrades/*.tres`，
> 护盾类取自 `data/equipment/*.tres`，血包直接回核心血量。新增商品无需改 UI，只需扩展生成器。

---

## 一、商店运行规则

| 项目 | 规则 |
|---|---|
| 出现时机 | 游戏进行满 **5 分钟** 后，在竞技场正中心 `Vector2.ZERO` 生成 |
| 存续 | 生成后**永久存在，不再消失** |
| 进入方式 | 玩家靠近后按 E 进入商店（交互优先级：神庙 > 商店 > 拾取物） |
| 暂停 | 进入商店即暂停游戏（`GameManager.pause_game`），离开商店恢复 |
| 货币 | 梦境碎片（`Player.dream_fragment`） |
| 刷新间隔 | 每 **60 秒** 随机刷新一次货架 |
| 货架数量 | 每次 **3 件** 商品，横向排开（与升级三选一同款） |
| 品类概率 | 属性类 30% / 技能类 30% / 护盾类 20% / 血包 20% |

## 四、购买规则

1. **扣款**：玩家选定商品后，`Shop` 先校验 `Player.dream_fragment >= 价格`，再调用
   `Player.spend_dream_fragment(价格)` 扣款，最后 `ShopProduct.apply(player)` 应用效果。
2. **余额不足**：不扣款、不发货，仅播放提示音与面板红闪提示（`ShopPanel.notify_insufficient`）。
3. **购买后**：面板标题栏实时刷新碎片余额，商品不消失（同一件可重复购买，直到 60 秒刷新）。
4. **结算统计**：属性/技能类商品经 `UpgradeManager.apply_upgrade` 应用，会正常计入
   技能种类上限（最多 5 种）与词条统计；护盾类计入装备槽。

## 五、与现有体系的关系（零侵入）

- **属性/技能类**：复用 `UpgradeManager.get_random_attribute_upgrade()` /
  `get_random_effect_upgrade()` 抽取词条，再走 `UpgradeManager.apply_upgrade()` 统一应用，
  与手动拾取技能书获得的新词条完全一致（含技能上限 5 种、满级 5 级规则）。
- **护盾类**：复用 `Player.equip_shield()` 与装备护盾组件，同类型叠加/不同类型替换规则不变。
- **血包**：复用 `Player.heal()`，仅补充血量，不干扰技能/装备。
- **输入**：商店经 `InputManager` 的 `SHOP_CHOICE` 上下文放行 LT/RT 左右选择、
  A 确认购买、ESC 关闭，遵守 `INPUT_ARCHITECTURE_SPEC.md`。
- **性能**：商店生成后仅单节点；商品刷新每 60 秒一次；交互范围探测节流 0.1s、
  视觉脉冲重绘节流 30fps，不对战斗帧率产生可感知影响。
