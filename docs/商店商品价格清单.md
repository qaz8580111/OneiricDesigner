# 中央商店商品及价格清单

> 用途：主场景中央商店（游戏开始即存在）的固定服务、价格体系与服务来源对照。
> 数据来源：`scripts/entities/Shop.gd`（固定服务构造与价格常量）、`scripts/resources/shop/ShopProduct.gd`（商品数据）。
> 装备化重构后，商店收敛为**三大固定服务**：恢复健康 / 随机装备 / 合成装备。
> 其中「恢复健康」「随机装备」是可直接「扣碎片即生效」的 `ShopProduct`；
> 「合成装备」是面板内的子视图，**同时消耗各槽位装备碎片与梦境碎片**合成保底稀有装备，
> 合成完成后弹出**结果反馈视图**展示产出的装备明细（与神庙「融合装备」同款反馈）。

---

## 一、商店运行规则

| 项目 | 规则 |
|---|---|
| 出现时机 | **游戏开始即存在**，在竞技场正中心 `Vector2.ZERO` 生成（`GameWorld._ready()` 调用一次） |
| 存续 | 生成后**永久存在，不再消失** |
| 进入方式 | 玩家靠近后按 E 进入商店（交互优先级：神庙 > 商店 > 拾取物） |
| 暂停 | 进入商店即暂停游戏（`GameManager.pause_game`），离开商店恢复 |
| 货币 | 恢复健康 / 随机装备 = 梦境碎片（`Player.dream_fragment`）；合成装备 = 各槽位装备碎片（`Player.get_equipment_fragment(slot)`）**+ 梦境碎片** |
| 刷新间隔 | **不刷新**：服务列表游戏开始即固定，面板不随机换货 |
| 选项数量 | 固定 **3 项**：恢复健康 / 随机装备 / 合成装备 |

---

## 二、价格体系总表

| 服务 | 货币 | 价格 |
|---|---|---|
| 恢复健康 | 梦境碎片 | **100**（消耗后直接把核心血补满） |
| 随机装备 | 梦境碎片 | **200**（获得一件随机稀有度的随机装备） |
| 合成装备 | 各槽位装备碎片 + 梦境碎片 | **3 个同槽位碎片 + 100 梦境碎片**（`EquipmentRecycler.CRAFT_FRAGMENT_COST` / `CRAFT_DREAM_COST`） |

> 价格常量定义在 `scripts/entities/Shop.gd` 常量区：
> `PRICE_HEAL_FULL = 100` / `PRICE_RANDOM_EQUIPMENT = 200`。
> 合成消耗定义在 `scripts/resources/equipment/EquipmentRecycler.gd`：
> `CRAFT_FRAGMENT_COST = 3`、`CRAFT_DREAM_COST = 100`，保底稀有度 `CRAFT_RARITY_FLOOR = EquipmentData.Rarity.RARE`。

## 三、各服务来源与效果明细

### 3.1 恢复健康（`ProductType.HEAL_FULL`）

| 项目 | 说明 |
|---|---|
| 效果 | 读取当前缺失血量（上限 − 当前核心血）后一次性 `Player.heal(missing)`，**直接满血** |
| 价格 | 100 梦境碎片 |
| 前置校验 | 已满血时拒绝购买（`Shop._is_fully_healed`），避免白扣碎片 |

> 效果由 `ShopProduct.apply()` 计算缺失量后调用 `Player.heal()`；无 `get_survival_state` / `heal` 接口则视为不可应用。

### 3.2 随机装备（`ProductType.RANDOM_EQUIPMENT`）

| 项目 | 说明 |
|---|---|
| 效果 | 调用 `UpgradeManager.generate_equipment()` 现场随机生成一件装备，直接放入背包（`Player.add_equipment_to_backpack`） |
| 价格 | 200 梦境碎片 |
| 前置校验 | 背包已满时拒绝购买（`Shop._is_backpack_full`），避免扣款后装备无处安放 |

**稀有度概率分布**（由 `UpgradeManager.EQUIPMENT_RARITY_WEIGHTS = [76, 20, 4]` 归一化得出，面板提示栏动态拼接）：

| 稀有度 | 概率 |
|---|---|
| 普通 | **76%** |
| 稀有 | **20%** |
| 史诗 | **4%** |

装备的其余构成（槽位、词条、特效、护盾、主动技能）与掉落、神庙「融合装备」共用同一生成器：

| 构成 | 生成规则（`EquipmentGenerator`） |
|---|---|
| 槽位 | 由 `EQUIPMENT_SLOT_WEIGHTS = [22, 20, 18, 14, 13, 13]` roll 出（武器/护甲/鞋子/盾牌/戒指/法宝） |
| 基础属性词条 | 条数按稀有度断崖递减（几何比≈0.25）；数值 = 模板最大值 × `randf_range(0.5, 1.0)` |
| 子弹特效 | 按稀有度权重命中后取 1~2 个，强度 1~3 级（复用叠层成长） |
| 护盾蓝图 | 仅盾牌槽携带，按稀有度概率附加护盾特效 |
| 主动技能 | 仅武器/戒指/法宝，命中概率 普通 5% / 稀有 25% / 史诗 60%，冷却 8/5/3 秒 ±1 抖动；整轮伤害倍率 普通 ×2.5 / 稀有 ×3.5 / 史诗 ×5.0 |

### 3.3 合成装备（面板子视图，非 `ShopProduct`）

| 项目 | 说明 |
|---|---|
| 入口 | 主视图第三项「合成装备」，点击/确认后**就地展开合成子视图**（不再用页签切换） |
| 子视图内容 | 6 个槽位合成按钮（武器/护甲/鞋子/盾牌/戒指/法宝）+ 「返回」按钮 |
| 消耗 | 3 个**同槽位装备碎片**（`CRAFT_FRAGMENT_COST`）**+ 100 梦境碎片**（`CRAFT_DREAM_COST`） |
| 产出 | `UpgradeManager.generate_equipment_with_floor(slot, CRAFT_RARITY_FLOOR)` 生成**保底稀有**的同槽位装备，直接入背包 |
| 前置校验 | 装备碎片不足 / 梦境碎片不足 / 背包已满时拒绝，不生成不扣任何货币 |
| 结果反馈 | 成功入背包后切到**结果反馈视图**（`ShopPanel.show_craft_result`），展示"合成成功！"+ `UpgradeManager.build_obtain_message(eq)` 的装备明细，玩家确认后关闭 |

> 合成走 `ShopPanel.craft_requested(slot)` → `Shop._on_craft_requested(slot)`；
> 装备碎片由分解装备产出（`EquipmentRecycler`），与梦境碎片是两套独立货币，合成需**同时**满足两者。

## 四、购买规则

1. **扣款**：玩家选定服务后，`Shop` 先校验 `Player.dream_fragment >= 价格`，再调用
   `Player.spend_dream_fragment(价格)` 扣款，最后 `ShopProduct.apply(player)` 应用效果。
2. **余额不足 / 已满血 / 背包已满**：不扣款、不发货，仅播放提示音与面板标题红闪提示（`ShopPanel.notify_failure`）。
3. **退款兜底**：发货阶段若竞态失败（如背包满），`Shop` 自动**退还已扣碎片**，保证玩家不白花钱。
4. **购买后**：面板标题栏实时刷新碎片余额；服务列表固定不变（同一服务可重复购买）。
5. **合成**：先校验装备碎片、梦境碎片与背包 → 生成装备 → 扣装备碎片 → 扣梦境碎片 → 入背包；
   任一后续步骤失败则**退还已扣的两种货币**（扣梦境碎片失败退还装备碎片，入背包失败退还两种货币），
   成功则弹出结果反馈视图。
6. **结算统计**：装备类经 `Player.add_equipment_to_backpack` 进入背包，穿戴后属性/特效/护盾/主动技能
   统一由 `EquipmentComponent` 汇总进 `UpgradeManager.recompute_stats()`。

## 五、与现有体系的关系（零侵入）

- **随机装备 / 合成装备**：复用 `UpgradeManager.generate_equipment()` /
  `generate_equipment_with_floor()`，与掉落、神庙「融合装备」走同一生成器，概率模型与词条模板完全一致。
- **恢复健康**：复用 `Player.heal()`，仅补充血量，不干扰装备。
- **血包掉落已移除**：血包不再出现在任何掉落表（`Enemy` / `GameWorld` 精英 / `StageDirector` Boss），
  只能从商店购买。
- **输入**：商店经 `InputManager` 的 `SHOP_CHOICE` 上下文放行 LT/RT 左右选择、
  A 确认购买/展开合成、ESC 返回/关闭，遵守 `INPUT_ARCHITECTURE_SPEC.md`。
- **性能**：商店生成后仅单节点；服务固定不刷新；交互范围探测节流 0.1s、
  视觉脉冲重绘节流 30fps，不对战斗帧率产生可感知影响。
