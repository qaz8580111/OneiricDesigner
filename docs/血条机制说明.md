# 🛡️ 《梦境设计师》生命值系统：分段护盾+核心血量混合模型

## 1. 系统概述与设计目标
- **系统名称**：`HybridHealthSystem` (混合生命系统)
- **核心定位**：将玩家生存状态分为“离散容错层（护盾）”与“连续致命层（核心血）”，为弹幕Roguelike提供三段式情绪节奏。
- **设计原则**：
    - **数据驱动**：所有数值配置必须通过 `Resource` 定义，禁止硬编码。
    - **信号解耦**：UI/音效/VFX 仅通过信号响应，严禁在逻辑脚本中直接引用表现层节点。
    - **双碰撞体适配**：严格复用现有 `Player.tscn` 的 20px物理体 + 18px判定体 架构。
    - **直播友好**：受击反馈必须具备强视觉/听觉辨识度，支持“碎盾计数”与“红血预警”。

## 2. 数据结构定义（Resource）

请创建以下两个自定义 Resource 脚本，作为系统唯一数据源：

### 2.1 `shield_data.gd`
```gdscript
class_name ShieldData
extends Resource

@export_group("基础属性")
@export var max_segments: int = 3          # 护盾段数上限
@export var segment_hp: float = 10.0       # 每段护盾吸收伤害值
@export var regen_delay: float = 5.0       # 脱战后回盾延迟(秒)
@export var regen_interval: float = 1.5    # 每段护盾恢复间隔(秒)

@export_group("表现配置")
@export var break_vfx: PackedScene         # 碎盾粒子特效
@export var hit_sfx: AudioStream           # 护盾受击音效(建议多音调)
@export var color_full: Color = Color.CYAN # 满盾颜色
@export var color_low: Color = Color.ORANGE # 仅剩1段时颜色
```

### 2.2 `core_health_data.gd`
```gdscript
class_name CoreHealthData
extends Resource

@export var max_hp: float = 100.0          # 核心血量上限
@export var critical_threshold: float = 0.3 # 红血预警阈值(30%)
@export var invincible_duration: float = 0.5 # 核心受击后无敌帧时长
@export var death_vfx: PackedScene         # 死亡特效
@export var critical_sfx: AudioStream      # 红血心跳/BGM滤镜触发音
```

## 3. 核心组件实现规范

### 3.1 `ShieldComponent.gd` (挂载于 Player.tscn)
- **职责**：管理护盾段数、再生计时器、伤害拦截。
- **关键逻辑**：
    - 暴露 `take_damage(amount: float) -> float` 方法，返回**穿透到核心血的剩余伤害**。
    - 使用 `Timer` 节点管理再生，脱战重置计时器，战斗中暂停。
    - 每次碎盾发射信号 `shield_segment_broken(current_segments: int)`。
    - 护盾归零时发射信号 `shield_depleted()`。
- **⚠️ 禁止事项**：不得直接修改 UI 纹理或播放音频，仅发信号。

### 3.2 `CoreHealthComponent.gd` (挂载于 Player.tscn)
- **职责**：管理核心血量、无敌帧、死亡判定。
- **关键逻辑**：
    - 接收 `ShieldComponent` 穿透的伤害。
    - 受击时启动无敌帧（角色 `modulate.a = 0.5` + Tween 闪烁）。
    - 血量 ≤ `critical_threshold` 时持续发射信号 `critical_state_active(is_active: bool)`。
    - 血量 ≤ 0 时发射信号 `player_died()`，并调用 `get_tree().paused = true` 防止死亡后继续受击。
- **双碰撞体集成**：在 `_on_hitbox_area_entered(area: Area2D)` 中调用 `ShieldComponent.take_damage()`，而非直接扣核心血。

### 3.3 `PlayerHealthController.gd` (协调器，挂载于 Player.tscn)
- **职责**：串联 Shield 与 CoreHealth，对外暴露统一接口。
- **公开API**：
    ```gdscript
    func apply_damage(amount: float, source_type: String) -> void
    func heal_shield(segments: int) -> void
    func heal_core(amount: float) -> void
    func get_survival_state() -> Dictionary  # 返回 {"shield": int, "core": float, "is_critical": bool}
    ```
- **信号转发**：将子组件信号统一转发为 `health_changed(state: Dictionary)`，供UI监听。

## 4. 信号通信契约（Signal Contract）

| 信号名 | 参数 | 发射时机 | 预期消费者 |
| :--- | :--- | :--- | :--- |
| `shield_segment_broken` | `current_segments: int` | 护盾段被击碎瞬间 | UI(更新图标), AudioManager(播放碎盾音), VFXManager(生成碎片) |
| `shield_depleted` | 无 | 护盾完全归零 | AudioManager(切换BGM低通), Camera2D(轻微震动) |
| `core_health_changed` | `current: float, max: float` | 核心血量变动 | UI(更新血条宽度/颜色) |
| `critical_state_active` | `is_active: bool` | 进入/退出红血状态 | UI(血条脉动Tween), AudioManager(BGM变调), PostProcess(屏幕泛红) |
| `player_died` | 无 | 核心血量≤0 | GameWorld(触发结算), UI(显示死亡面板) |

> ⚠️ **强制约束**：所有信号必须在对应 Component 的 `_ready()` 中使用 `add_user_signal()` 显式声明，确保编辑器自动补全和类型安全。

## 5. 与现有系统集成点

### 5.1 碰撞检测集成
在 `Player.tscn` 的 `HitboxArea` (18px判定体) 的 `area_entered` 信号回调中：
```gdscript
func _on_hitbox_area_entered(area: Area2D):
    if area.is_in_group("enemy_projectile"):
        var damage = area.get_meta("damage", 10.0)
        $HealthController.apply_damage(damage, "projectile")
        area.queue_free()  # 弹幕命中即销毁，避免多段判定
```

### 5.2 词条系统集成预留
- `ShieldData` 和 `CoreHealthData` 必须支持运行时替换：
    ```gdscript
    func apply_shield_mod(new_data: ShieldData) -> void:
        shield_data = new_data
        emit_signal("shield_config_changed", new_data)
    ```
- 词条效果示例：“击杀敌人回复1段护盾” → 监听 `enemy_killed` 信号，调用 `heal_shield(1)`。
